# YouTube Services Bot

Telegram-бот: заявки на создание YouTube-канала и подключение монетизации,
накрутка (подписчики/просмотры/лайки через SMM-панель), покупка Telegram Stars,
пополнение баланса переводом на карту с подтверждением админом.

## Запуск

```bash
npm install
cp .env.example .env   # заполнить токены и ключи
npx prisma migrate dev --name init
npm run dev
```

## Важные заметки

- **Накрутка** идёт через внешнюю SMM-панель (`src/services/boostProvider.ts`).
  Нужен рабочий аккаунт в SMM-панели (например JAP, SMMflow или аналог) —
  оттуда берутся `SMM_API_URL`, `SMM_API_KEY` и ID нужных услуг для YouTube
  (подписчики/просмотры/лайки), прописать в `.env`.
- **Telegram Stars** — официального API для покупки звёзд третьим лицом нет.
  `src/services/starsProvider.ts` сейчас — заглушка, которая ставит покупку
  в статус "pending" (не списывает деньги зря, но и не выдаёт звёзды сама).
  Подключить реальную выдачу — через Fragment.com (неофициально) либо
  сделать ручное подтверждение админом.
- **Оплата картой** — автоматической приёма платежей нет (это невозможно без
  лицензированного провайдера). Клиент переводит на карту, присылает скрин,
  админ подтверждает в боте-уведомителе. Реквизиты берутся из `Settings`
  (`card_number`, `card_holder`), меняются командой `/setcard`.
- Цены и курсы (стоимость услуг, курс звезды, мин. сумма пополнения)
  меняются админ-командами `/setprice`, `/setstarrate`, `/settopupmin`
  — см. `src/bot/admin.ts`. Список команд: `/stats`, `/backup`, `/checkbalance`.
- `session()` сейчас в памяти процесса — если планируется несколько
  инстансов бота или продакшен с перезапусками, замените на
  `@grammyjs/storage-*` (например Redis) для сохранности диалогов.

## Бэкапы и восстановление

Диск Render эфемерный, наружу файл не положить, поэтому дампы уходят
в админский чат Telegram — раз в сутки автоматически (`src/services/backup.ts`).
Вручную: `/backup`.

В дампе лежат **все** таблицы: юзеры с балансами, транзакции, заявки,
накрутки, покупки звёзд, настройки. Это обычный JSON, его можно просто открыть.

Если база пропала, свежий дамп лежит в чате с админским ботом:

```bash
# 1. скачать backup-ДАТА.json из Telegram и положить в корень проекта
# 2. указать DATABASE_URL новой базы и восстановить
DATABASE_URL="postgres://..." npm run restore -- backup-2026-10-26.json
# 3. этот же DATABASE_URL прописать в env на Render и задеплоить
```

`restore` никогда не удаляет данные — только `upsert` по первичному ключу,
так что прерванный прогон безопасен, повторный запуск дозапишет остальное.
Если в целевой базе уже есть юзеры, скрипт откажется работать без `--force`.

Если база пересоздалась с нуля, бот сам напишет в админский чат
`🚨 ПОТЕРЯ БАЛАНСОВ` со сравнением «было / стало» — это самая опасная
поломка, потому что бот при ней работает как ни в чём не бывало.
